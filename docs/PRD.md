> Product Requirements Document v1.4
> 수정일: 2026.05.19

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | Peek |
| 한 줄 설명 | 저장만 해둔 링크를 AI가 다시 읽고, 반복 정보는 병합하며, 고유 정보는 살려 나만의 콘텐츠 초안으로 바꿔주는 개인 리서치 보관함 |

| 타겟 사용자 | 직접 저장한 링크를 블로그 글, 유튜브 기획안, 카드뉴스, 발표·공부 노트, 포트폴리오 자료로 바꾸고 싶은 개인 사용자 |

| MVP 입력 방식 | URL + 저장 의도 메모(선택) |
| 확장 방향 | YouTube 자막 기반 영상 링크, 인스타그램/릴스/이미지 스크랩, PDF/논문 등 |

### 1-1. 포지셔닝 원칙

Peek는 뉴스/트렌드 조사 에이전트나 PR·마케팅용 미디어 모니터링 도구가 아니다.
Meltwater, Cision, Feedly처럼 외부 뉴스·미디어·소셜 데이터를 대량 수집해 업계 동향을 알려주는 서비스와 다르게,
Peek는 사용자가 직접 저장한 링크에서 시작한다.

**Peek의 출발점은 세상의 모든 정보가 아니라, 사용자가 저장한 정보다.**

사용자가 저장했다는 것은 이미 관심과 의도가 있었다는 뜻이다. Peek는 그 의도를 되살려,
저장된 링크를 개인의 글감, 리서치 노트, 콘텐츠 초안, 포트폴리오 자료 같은 콘텐츠 자산으로 바꾼다.

### 1-2. 피해야 할 포지셔닝

다음 표현은 PR/마케팅 뉴스 인텔리전스 도구처럼 보일 수 있으므로 핵심 카피에서 피한다.

- AI가 트렌드를 분석해 인사이트를 제공합니다.
- 마케팅 리포트를 자동 생성합니다.
- 뉴스와 소셜 데이터를 정리합니다.
- 업계 동향을 자동으로 모니터링합니다.

대신 다음 방향으로 표현한다.

- 저장만 해둔 링크를 다시 읽지 않아도, 내가 저장한 이유와 핵심 정보를 되살려 나만의 콘텐츠 초안으로 바꿔준다.
- Peek는 세상의 모든 뉴스를 수집하지 않는다. 사용자가 직접 저장한 링크만 분석한다.
- 반복되는 정보는 병합하고, 각 링크에만 있는 고유한 주장·사례·데이터·관점은 최종 콘텐츠에 살린다.
- 결과물은 단순 요약 리포트가 아니라, 사용자가 바로 수정하고 활용할 수 있는 콘텐츠 초안이다.

## 2. 문제 정의 (Problem Statement)

### 2-1. 배경

AI 시대에 정보와 콘텐츠의 생산량은 빠르게 증가하고 있다. 사용자는 웹, 메신저, 커뮤니티, SNS, 뉴스레터 등 다양한 경로에서 유용해 보이는 링크를 발견하고 저장한다. 하지만 저장한 정보가 많아질수록 다음과 같은 문제가 생긴다.

- 좋은 정보를 많이 스크랩하지만, 다시 보려고 하면 어디에 저장했는지 찾기 어렵다.
- 링크가 폴더 없이 쌓이거나, 직접 분류해야 해서 정리가 귀찮다.
- 비슷한 내용의 글을 여러 개 저장했지만, 무엇이 중복이고 무엇이 새로운 정보인지 알기 어렵다.
- 링크별 요약은 도움이 되지만, 여러 링크를 모아 하나의 흐름으로 이해하기는 어렵다.
- 결과적으로 저장은 많이 하지만, 저장한 정보를 나만의 글감이나 콘텐츠 자산으로 활용하지 못한다.

**관련 수치**
- 2025년 기준 전체 직장인의 80%가 정보 과부하를 경험 (2020년 60%에서 증가)
- 인간이 하나의 콘텐츠에 집중할 수 있는 평균 시간: 47초 (2004년 2분 30초에서 급감)
- 전 세계 인터넷 사용자의 73%가 매일 3개 이상의 뉴스 앱·웹사이트에 접속
- 소셜미디어 사용자의 35%는 매주 정보 피로(information fatigue)를 경험

### 2-2. 사용자가 느끼는 핵심 불편함

1. **분류의 귀찮음** — 좋은 링크를 저장할 때마다 폴더나 태그를 직접 지정해야 하는 과정이 번거롭다.
2. **중복 정보의 피로감** — 여러 글이 비슷한 내용을 반복하지만, 무엇이 중복이고 무엇이 새로운 정보인지 직접 비교해야 한다.
3. **재활용의 어려움** — 저장한 링크들을 글쓰기, 공부, 기획, 발표, 포트폴리오에 활용하고 싶어도 정리되지 않아 다시 읽는 데 시간이 많이 든다.
4. **저장 의도 상실** — 나중에 다시 보면 왜 저장했는지, 어떤 콘텐츠에 쓰려 했는지 기억나지 않는다.
5. **저장과 이해의 단절** — 기존 스크랩/북마크 도구는 저장을 도와주지만, 저장된 정보를 활용 가능한 콘텐츠 구조로 바꿔주지는 못한다.

### 2-3. 핵심 인사이트

> 사람들은 좋은 정보를 저장하지만, 저장된 정보가 곧바로 자신의 지식이 되지는 않는다.
> Peek는 URL과 저장 의도 메모를 바탕으로 저장한 이유를 되살리고,
> 반복 정보는 병합하며 고유 정보는 보존해 사용자가 바로 수정하고 활용할 수 있는 콘텐츠 초안으로 바꿔준다.

## 3. 프로젝트 목표 (Goals)

### Primary Goal
사용자가 직접 저장한 링크를 AI가 읽고, 저장 의도에 맞게 분류한 뒤, 폴더별로 나만의 콘텐츠 초안을 생성한다.

### Secondary Goals
- 링크를 저장하는 순간 AI가 내용을 파악해 적절한 스마트 폴더에 자동 배치한다.
- 같은 폴더 안의 여러 링크를 정보 포인트 단위로 비교해 반복 정보는 병합하고 고유 정보는 보존한다.
- 저장된 링크가 많아질수록 사용자의 개인 리서치 보관함과 콘텐츠 자산이 된다.
- 사용자의 저장 의도 메모를 반영해 블로그 초안, 유튜브 기획안, 카드뉴스 구성안, 발표·공부 노트 같은 결과물로 전환한다.

### Non-Goals (MVP 제외)
- 본문 직접 붙여넣기 입력 방식
- YouTube 영상 자막 자동 추출
- 인스타그램/릴스/이미지 콘텐츠 분석
- 브라우저 확장 프로그램
- 카카오톡/디스코드/슬랙 자동 연동
- 공유 링크 및 소셜 기능 / 협업 기능
- 서버 사이드 프록시 크롤러
- 외부 뉴스·미디어·소셜 데이터 자동 수집 및 브랜드 모니터링
- 업계 동향 알림, PR 리포트, 미디어 인텔리전스 대시보드

## 4. MVP 범위

### 4-1. 입력 방식 (v1.3 핵심 변경)

**URL + 메모(선택)만 입력받는다.**

```
1. URL 입력
2. 저장 의도 메모 입력 (선택 — 이 링크를 저장하는 이유, 활용 목적, 만들고 싶은 콘텐츠)
3. 저장 버튼 클릭
4. Claude API가 URL을 직접 fetch해서 페이지 내용 분석
5. 분석 결과 자동 저장
```

**제목 입력란 제거** — AI가 페이지에서 자동 파싱하므로 불필요.
**본문 붙여넣기 제거** — UX 단순화 우선, 한계는 v2.0에서 해결.
**저장 의도 메모 유지** — 단순 메모가 아니라 콘텐츠 변환 방향을 정하는 핵심 입력이다.

### 4-2. 크롤링 가능 범위

MVP에서는 Claude API의 URL fetch 기능으로 페이지를 직접 읽는다.
CORS 제약이 없는 서버 사이드 fetch 방식이므로 대부분의 공개 페이지 지원.

| 보통 가능 | 보통 불가 |
|---|---|
| GitHub, MDN, 공식 문서 | 로그인 필요 페이지 |
| Dev.to, Velog, 미디엄(공개) | 페이월 기사 |
| BBC, Reuters 등 외신 | 일부 JS 렌더링 전용 SPA |
| 브런치, 기술 블로그 대부분 | 카카오, 네이버 일부 |

### 4-3. 크롤링 실패 시 처리

```
URL fetch 실패
      ↓
"이 페이지는 직접 읽어올 수 없어요."
+ 메모가 있으면 → 메모 기반 최소 분류만 제공
+ 메모가 없으면 → "메모를 남기면 최소 분류가 가능합니다" 안내
+ 수동으로 제목만 입력해서 저장하는 옵션 제공
```

### 4-4. 48시간 기준 우선순위

| 기능 | 난이도 | 우선순위 |
|---|---|---|
| 스크랩 인박스 (URL + 메모) | 하 | ✅ MVP 필수 |
| Claude API URL fetch + 분석 | 중 | ✅ MVP 필수 |
| 스마트 폴더 자동 분류 | 중 | ✅ MVP 필수 |
| 링크 목록 + 카드 UI | 하 | ✅ MVP 필수 |
| 나만의 콘텐츠 생성 (정보 포인트 병합 포함) | 높 | ✅ MVP 핵심 |
| 콘텐츠 아카이브 조회 | 중 | ⚠️ 시간 남으면 |
| Markdown 복사 | 하 | ⚠️ 시간 남으면 |

## 5. 핵심 기능 명세 (Feature Specification)

### 5-1. 스크랩 인박스

**설명**
URL 하나만 붙여넣으면 AI가 알아서 읽고 분류하는 공간.
폴더를 고르거나 제목을 입력하거나 본문을 붙여넣을 필요가 없다.

**입력 필드**
- URL (필수)
- 저장 의도 메모 (선택 — 이 링크를 저장한 이유, 활용 목적, 만들고 싶은 콘텐츠)

**동작 흐름**
```
저장 버튼 클릭
      ↓
Claude API가 URL 페이지 fetch
      ↓
성공 → 제목 자동 파싱 + 3줄 요약 + 키워드 + 폴더 분류
실패 → 에러 메시지 + 메모 기반 최소 분류 or 수동 제목 입력 옵션
```

**UX 메시지**
> "URL만 붙여넣으세요. 나머지는 Peek가 합니다."

---

### 5-2. AI 자동 분석 (링크 저장 시 1회 호출)

**입력**
- URL (Claude API가 직접 fetch)
- 저장 의도 메모 (선택 — 있으면 분류와 콘텐츠 생성 방향에 활용)
- 기존 폴더 목록 + 폴더별 키워드

**출력**
- 제목 (페이지에서 자동 파싱)
- 3줄 요약
- 핵심 키워드 3~5개
- 추천 스마트 폴더명
- 콘텐츠 유형 (실무 팁 / 사례 모음 / 의견·칼럼 / 자료·근거 / 튜토리얼 / 기타)

**AI 프롬프트 방향**
```
다음 URL의 페이지 내용을 읽고 JSON으로 반환해줘.
사용자 메모가 있다면 분류 힌트로 활용해줘.

반환 항목:
- title: 페이지 제목
- summary: 핵심 내용 3줄 요약 (각 줄 30자 이내)
- keywords: 핵심 키워드 3~5개
- suggestedFolder: 기존 폴더 우선, 없으면 새 폴더명 제안
- contentType: 실무 팁/사례 모음/의견·칼럼/자료·근거/튜토리얼/기타
- reason: 폴더 추천 이유 1~2문장
```

---

### 5-3. 스마트 폴더 자동 분류

**기능 목록**
- AI 추천 폴더 자동 생성 / 기존 폴더에 자동 배치
- 폴더명 수동 수정 / 링크 폴더 수동 변경
- 폴더 카드: 링크 수 / 키워드 수 / 콘텐츠 생성 가능 상태 / 마지막 업데이트
- 링크 2개 이상 쌓인 폴더에 "콘텐츠 만들기" 버튼 활성화

**폴더 카드 예시**

| 항목 | 예시 |
|---|---|
| 폴더명 | AI와 콘텐츠 제작 |
| 링크 수 | 8개 |
| 키워드 수 | 12개 |
| 마지막 업데이트 | 2시간 전 |
| 상태 | ✅ 콘텐츠 생성 가능 |

---

### 5-4. 나만의 콘텐츠 생성 — 핵심 차별점

**설명**
같은 폴더 안의 여러 링크를 바탕으로 정보 포인트를 추출하고 하나의 콘텐츠 초안을 생성한다.
반복 정보 병합, 고유 정보 보존, 노이즈 제거, 최종 초안 생성을 **단일 AI 호출**로 처리한다.

**트리거**
- 폴더에 링크 2개 이상 → "콘텐츠 만들기" 버튼 활성화
- 폴더 상세에서 직접 클릭

**생성 콘텐츠 구조**
```
# [자동 생성 제목]
## 핵심 요약
## 중복 제거율
## 병합된 반복 정보
## 보존된 고유 정보
## 제거된 노이즈
## 바로 활용할 수 있는 정리
## 더 알아볼 질문
## 출처 표시 포함 최종 초안
```

### 5-5. 콘텐츠 아카이브

**기능 목록**
- 생성된 콘텐츠 목록 (최신순 / 폴더별 필터)
- 콘텐츠 상세 보기 / 출처 링크 확인
- 콘텐츠 삭제 / 다시 생성

## 6. 화면 구조 (4탭)

```
App
├── 탭 1: 스크랩     URL + 메모(선택) 입력
│   ├── URL 입력 (필수)
│   ├── 메모 입력 (선택)
│   ├── 저장 버튼
│   └── AI 분석 결과 표시
│       ├── 성공: 제목 / 요약 / 키워드 / 자동 배치 폴더
│       └── 실패: 에러 메시지 + 수동 제목 입력 옵션
│
├── 탭 2: 폴더       스마트 폴더 목록
```

## 9. 기술 스택

| 역할 | 기술 |
|---|---|
| UI | React + Vite |
| 스타일 | Tailwind CSS |
| 데이터 저장 | LocalStorage |
| 상태 관리 | React Context + 커스텀 훅 |
| AI 분석 + URL fetch | Express API 서버 + Claude API |
| 출력 | Markdown 복사 |

**기술 방향**
- MVP는 React/Vite 기반의 브라우저 앱으로 개발한다.
- 사용자의 스크랩, 폴더, 생성 콘텐츠 데이터는 LocalStorage에 저장한다.
- Supabase/DB 연동은 MVP 범위에서 제외하고, 데이터 구조가 안정된 뒤 v2.0 이후 검토한다.
- Claude API 키 보호를 위해 AI 호출은 최소 Express 서버를 통해 처리한다.

## 10. 핵심 사용자 플로우

### Flow 1. 링크 저장
```
1. 나중에 글감이나 자료로 쓰고 싶은 웹 글 발견
2. Peek에 URL 붙여넣기 (+ 선택적으로 저장 의도 메모 한 줄)
3. Claude API가 URL 페이지를 직접 읽고 분석
4. 제목 자동 파싱 + 3줄 요약 + 키워드 + 폴더 자동 배치
5. 링크 카드로 저장 완료
```

### Flow 2. 폴더 확인
```
1. 같은 주제의 링크가 여러 개 쌓임
2. 폴더 카드에서 링크 수 / 키워드 수 / 콘텐츠 생성 가능 상태 확인
3. 관련 링크를 모아 저장 의도에 맞는 콘텐츠 초안 생성
```

### Flow 3. 나만의 콘텐츠 생성
```
1. 폴더에서 "콘텐츠 만들기" 클릭
2. AI가 폴더 내 링크들을 비교
3. 반복 정보는 하나로 병합하고, 각 링크의 고유 정보는 보존
4. 중복 제거율과 병합·보존 내역을 포함한 구조화된 초안 생성
5. 읽거나 Markdown으로 복사해 활용
```

## 12. 엣지케이스 처리

| 상황 | 처리 방법 |
|---|---|
| URL fetch 실패 (CORS, 페이월 등) | "이 페이지는 직접 읽어올 수 없어요" + 메모 기반 최소 분류 or 수동 제목 입력 |
| 메모 없이 fetch 실패 | "메모를 남기면 최소 분류가 가능합니다" 안내 |
| 유효하지 않은 URL | URL 형식 검증 후 즉시 에러 메시지 |
| AI 분석 실패 | URL + 제목만으로 수동 저장 후 나중에 다시 분석 가능 |
| 적절한 폴더 없음 | 새 폴더 생성 제안 |
| 폴더 내 링크 2개 미만 | 콘텐츠 만들기 버튼 비활성화 + "링크 N개 더 필요" 안내 |
| 중복 제거율 낮음 | "반복 정보가 적고 고유 관점이 많은 초안입니다" 표시 |
| 중복 제거율 높음 | "반복 정보가 많아 병합 비중이 높은 초안입니다" 표시 |
| LocalStorage 용량 초과 | 오래된 콘텐츠 삭제 또는 Markdown 내보내기 안내 |

## 13. 기존 서비스와의 차별점

| 구분 | 일반 북마크 앱 | AI 요약 앱 | 대형 리서치 도구 | Peek |
|---|---|---|---|---|
| 핵심 목적 | 저장 | 빠른 요약 | 외부 정보 조사·모니터링 | 내가 저장한 링크를 내 콘텐츠로 재구성 |
| 입력 방식 | URL / 북마크 | URL / 문서 | 외부 뉴스·미디어·소셜 데이터 | 내가 직접 저장한 URL + 저장 의도 메모 |
| 분류 방식 | 사용자 직접 지정 | 일부 자동 태깅 | 주제·브랜드·키워드 기반 추적 | 내 저장 링크와 의도 기반 자동 폴더 생성·배치 |
| 중복 처리 | 없음 | 없음 | 사용자 직접 비교 | 반복 정보 병합 + 고유 정보 보존 |
| 결과물 | 저장 목록 | 요약 카드 | 질의응답/노트 | 출처 표시가 포함된 콘텐츠 초안 |
| 활용 목적 | 나중에 읽기 | 빠르게 훑기 | 세상에서 무슨 일이 일어나는지 파악 | 내가 왜 저장했는지 되살리고 바로 재활용 |

### 13-1. PR/마케팅 인텔리전스 도구와의 차이

| 구분 | PR/마케팅 뉴스 정리 도구 | Peek |
|---|---|---|
| 출발점 | 외부 뉴스, 미디어, 소셜 데이터 자동 수집 | 사용자가 직접 저장한 링크 |
| 목적 | 업계 동향 파악, 브랜드 모니터링, 리포트 | 내가 저장한 자료를 내 콘텐츠로 전환 |
| 사용자 | PR팀, 마케팅팀, 기업 커뮤니케이션 담당자 | 개인 창작자, 대학생, 취준생, 블로거, 마케터 지망생 |
| 결과물 | 트렌드 리포트, 미디어 인사이트, 알림 | 블로그 초안, 유튜브 기획안, 카드뉴스, 리서치 노트 |
| 핵심 가치 | 세상에서 무슨 일이 일어나는지 알려줌 | 내가 왜 저장했는지 되살리고, 쓸 수 있는 결과물로 바꿔줌 |
| AI 처리 방식 | 대량 정보 요약·분석 | 반복 정보는 병합, 고유 정보는 보존 |

## 15. 최종 제품 정의

> **Peek는 사용자가 직접 저장한 링크를 AI가 다시 읽고, 저장 의도를 되살리며, 반복 정보는 병합하고
