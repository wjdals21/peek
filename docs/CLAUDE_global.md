# CLAUDE.md (전역)

이 파일은 모든 프로젝트에 공통으로 적용되는 원칙을 정의한다.
프로젝트별 특화 내용(기술 스택, 폴더 구조, 명령어 등)은 각 프로젝트의 `CLAUDE.md`에 기술한다.

```
~/.claude/CLAUDE.md             ← 이 파일: 모든 프로젝트 공통 원칙
└── {project}/CLAUDE.md         ← 프로젝트 특화: 기술 스택, 폴더 구조, 명령어, 개발 범위
```

> 프로젝트 `CLAUDE.md`에는 이 전역 파일과 중복되는 내용을 기술하지 않는다.
> 전역 파일에는 특정 기술(React, Vue, Vanilla JS 등)에 종속된 내용을 기술하지 않는다.

---

## 작업 원칙

- 코드 또는 문서 작성 전 반드시 **기획안을 먼저 작성**하고 사용자 승인을 받은 후 작업을 시작한다.
- 기획 없이 임의로 구현하지 않는다.
- 섹션·기능 단위로 나눠 단계별로 진행한다.

### 기획 → 승인 → 구현 흐름

1. 작업 범위와 구현 방법을 계획으로 정리해 제시한다.
2. 사용자 승인 후 구현을 시작한다.
3. 구현 완료 후 브라우저 또는 테스트로 동작을 검증한다.

## 코드 스타일

### 네이밍

- 컴포넌트 파일·함수: PascalCase (`ProductCard.jsx`)
- 일반 함수·변수: camelCase (`handleSave`)
- 상수: UPPER_SNAKE_CASE (`MAX_RETRY_COUNT`)

### 일반 코드 원칙

- 불필요한 추상화·기능 추가 금지 (요구사항 범위 내에서만 구현)
- 에러 처리는 시스템 경계(사용자 입력, 외부 API)에서만 수행
- 주석은 WHY가 비명확한 경우에만 작성, WHAT 설명 주석 금지

### 스타일링 원칙

- 유틸리티 클래스 우선, 인라인 `style` 속성 사용 금지
- 클래스가 길어질 경우 줄바꿈으로 가독성 유지

### 상태 관리 원칙

- 로컬 UI 상태(모달 열림 등): 컴포넌트 내 지역 상태로 관리
- 전역 상태: 프로젝트에서 선택한 상태 관리 방식 사용 (프로젝트 `CLAUDE.md` 참조)
- props drilling 3단계 이상 금지

## 브랜치 전략 (GitHub Flow 기반)

```
main          # 배포 가능한 안정 브랜치, 직접 push 금지
└── feature/  # 기능 개발 (예: feature/scrap-inbox)
└── fix/      # 버그 수정 (예: fix/folder-filter)
└── hotfix/   # 긴급 수정 (예: hotfix/api-timeout)
```

- 작업 단위로 브랜치 생성 → PR → main 머지

---

## 커밋 컨벤션

- 접두사 사용: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`
- 예: `feat: 스크랩 인박스 UI 구현`, `fix: 폴더 자동 분류 오류 수정`
- 커밋 메시지는 한국어로 작성한다.
